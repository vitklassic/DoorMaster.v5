## Дефекты, найденные при тестировании

- **C11 (P2): скрипт `dev` не запускался в CMD Windows.** ✅ Исправлено 2026-11-06: `npm run dev` вызывает кроссплатформенный `scripts/start-expo.js`, который задаёт `EXPO_NO_TELEMETRY=1` и передаёт аргументы Expo. `npm run dev -- --help` и `typecheck` проходят. Изменение ещё не закоммичено.
- **C12 (P0): регистрация по инвайту отклоняла рабочий код.** Клиент `isInviteCodeValid` ожидал boolean, а RPC `is_valid_invite_code` по контракту возвращает `company_id uuid` или `null`. Горячее исправление внесено в `repo/lib/backend/inviteApi.ts`, `typecheck` проходит, сценарий регистрации монтажника подтверждён. Включено в коммит `82923f2` и отправлено на GitHub.
- **C13 (P1): на панели менеджера не загружался список монтажников.** ✅ Исправлено 2026-11-06: запрос переведён с несуществующего `profiles.email` на `display_name`. В браузере подтверждены `Всего: 1` и отображение `doormaste.v4`. Изменение ещё не закоммичено.
- **C14 (P1): кнопка черновика «Завершить замер» не меняла статус.** ✅ Исправлено 2026-11-06: переименована в «Сохранить и выйти», что соответствует фактическому поведению. `typecheck` проходит; отдельная визуальная проверка не проводилась. Изменение ещё не закоммичено.
- **C15 (P2): требование к этажам уточнено заказчиком.** Оба этажа необязательны и их можно пропустить. ✅ Исправлено 2026-11-06: пустой этаж объекта или проёма скрывается в приложении и PDF, а не выводится как «не указано». В браузере проверено: этаж объекта `3` виден, пустой этаж проёма исчез. Изменение ещё не закоммичено.
- **C16 (P1): иконку у пароля можно было принять за подтверждение.** ✅ Исправлено 2026-11-06: добавлены `Eye`/`EyeOff` и переключение видимости пароля; Enter по-прежнему отправляет форму. `typecheck` проходит; отдельная визуальная проверка не проводилась. Изменение ещё не закоммичено.
- **C17 (P0): фото с телефона сохранялось битым — в Storage уходил 14-байтовый текст `File not found` вместо JPEG.** Двойная причина: `fetch(asset.uri)` в Expo Go не отдаёт байты файла, а Hermes не поддерживает `Blob` из `ArrayBuffer` (`Creating blobs from 'ArrayBuffer' and 'ArrayBufferView' are not supported`). ✅ Исправлено 2026-11-06: на native фото загружается напрямую с диска через `expo-file-system` `UploadTask` (BINARY_CONTENT) в Storage REST API с `x-upsert: true`; web-путь через blob не изменён. Затронуты: `lib/measurements/photo.ts`, `photo.native.ts`, `photo.web.ts`, `lib/backend/photoStorage.ts`, `app/(tabs)/index.tsx`, `app/(tabs)/history.tsx`. Подтверждено: реальный снимок камеры 779 КБ (JPEG с EXIF) прочитан из облака и отображается и на телефоне, и в web-панели менеджера. Включены в коммит `82923f2` и отправлены на GitHub.
- **C18 (P1): после пересъёмки того же проёма (upsert в тот же путь Storage) показывалась старая картинка из кэша.** ✅ Исправлено 2026-11-06: после успешной загрузки `invalidatePhoto(path)` сбрасывает кэш подписанного URL и увеличивает `photoVersion`; `usePhotoUrl` перечитывает URL при смене версии, поэтому RN Image получает новый URL и не берёт старый кэш. Подтверждено на телефоне: после Reload отображается последнее реальное фото. Включены в коммит `82923f2` и отправлены на GitHub.
- **C19 (P0): на Android PDF нельзя было отправить, а в созданном отчёте отсутствовало фото.** Expo Go SDK 57 запрещает `expo-file-system/legacy` и `expo-sharing` читать файл из `cache/Print` (`isn't movable/readable`, `Not allowed to read file under given URL`), а `file://` в HTML при печати не загружался. ✅ Исправлено 2026-11-06: `Print.printToFileAsync({ base64: true })` возвращает содержимое PDF, которое записывается в собственный файл в корне кэша; фото дополнительно встраивается в HTML как `data:image/jpeg;base64`. Добавлены раздельные действия «Просмотреть / сохранить PDF» (`Print.printAsync`) и «Отправить PDF» (`Sharing.shareAsync`). Подтверждено на телефоне: фото видно в предпросмотре, сохранённом PDF и PDF, открытом после отправки через мессенджер. Затронуты `shareReport.native.ts`, `shareReport.ts`, `shareReport.web.ts`, `MeasurementDetail.tsx`. Включены в коммит `82923f2` и отправлены на GitHub.
- **Диагностика (оставить до завершения приёмки):** в `PhotoStep` и `MeasurementDetail` ошибки фото/PDF показывают реальную причину (`error.message`) вместо общей фразы — это помогло поймать C17 и C19.
