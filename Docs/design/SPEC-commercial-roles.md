# DoorMaster — ТЗ (черновик): структура данных и роли компаний

Статус: черновик Commercial 2026-11-07, утверждён заказчиком устно. Код не затрагивает.
Автор роли: Commercial. Приёмка: Архитектор + заказчик.

## 1. Иерархия данных

```
Владелец сервиса (супер-админ)  → видит ВСЁ: все компании, магазины, замеры, пользователей
        ▼
Компания (сеть, юрлицо) — на компанию оформляется подписка
        ├── Директор компании → видит ВСЕ магазины своей сети (только в мульти-магазинном тарифе)
        └── Магазин 1 … Магазин N
                ├── Менеджеры магазина → видят весь свой магазин
                └── Монтажники → видят ТОЛЬКО свои замеры
```

## 2. Роли

| Роль | Что видит | Где реализовано |
| --- | --- | --- |
| Супер-админ (владелец сервиса) | Все компании, магазины, замеры, пользователи | ❌ Новая роль, вне RLS компаний |
| Директор компании | Все магазины своей компании + сводная информация по сети | ❌ Новая роль, зависит от тарифа |
| Менеджер магазина | Все замеры своего магазина | ✅ Частично: сейчас «менеджер компании» = менеджер магазина |
| Монтажник | Только свои замеры | ✅ Работает (T11/C20) |

Правило изоляции: магазин не видит другие магазины даже внутри своей компании.
Чужие компании недоступны полностью (RLS уже гарантирует).

## 3. Зависимость от тарифа

- Тариф «1 магазин»: роль директора отсутствует, менеджер видит весь свой магазин.
- Тариф «несколько магазинов»: появляется роль директора и панель директора.
- Количество магазинов в компании — параметр подписки (ограничение по тарифу).

## 4. Панель «Директор» (новый экран)

Не фильтр в панели менеджера, а отдельная панель:

1. Список магазинов компании (название, количество замеров, менеджеров, монтажников).
2. Просмотр замеров любого своего магазина (read-only или как менеджер — уточнить).
3. Сводная информация по сети: всего замеров, активность по магазинам.
4. Управление магазинами: добавить магазин (в пределах тарифа) — уточнить.

## 5. Влияние на данные (для будущего обсуждения с Архитектором/Интегратором)

- Новая сущность «магазин» (shop/store) между компанией и пользователями/замерами.
- Замер и пользователь привязываются к магазину, а не напрямую к компании.
- Роль `director` в профиле пользователя.
- RLS: директор — по `company_id`, менеджер — по `shop_id`, монтажник — по `user_id`.
- Супер-админ — сервисная роль вне компаний.

## 6. Открытые вопросы заказчику

1. Менеджер может работать в нескольких магазинах одной сети?
2. Директор — только смотрит, или может редактировать замеры любого магазина?
3. Кто создаёт магазин: директор сам или мы (владельцы сервиса)?
4. Может ли монтажник числиться в двух магазинах?
5. Супер-админ — это только ты, или позже будет команда поддержки?
