# Доработка DoorMaster после повторного ручного теста

**Дата требований:** 2026-11-06.
**Статус:** зафиксировано заказчиком; не реализовано.
**Источник:** полный ручной сценарий — менеджер создал код, зарегистрирован ещё один монтажник, новый монтажник сразу появился в окне менеджера.

Документ объединяет текущие задачи T10–T14 и будущее направление F1. Ранее принятые T8 и исправления фото/PDF не отменяются.

## T10. Тестовый режим с полной диагностикой

### Требование

Создать запускатель `start-door-master-test.cmd`, который без ручного ввода команд запускает приложение в тестовом режиме и сразу включает полный вывод ошибок.

- Для каждой ошибки доступны исходное сообщение, тип, стек/`cause`, действие пользователя, платформа и время; для сетевых/Supabase-ошибок — код и детали ответа.
- Полные ошибки показываются с первого запуска теста, а не добавляются после нескольких неудачных попыток.
- Существующий показ полных ошибок фото/PDF в тестовом режиме сохранить.
- Пароли, токены, ключи и содержимое приватных URL в журнал не записывать.
- Обычный/production-режим сохраняет понятные пользовательские сообщения без внутренних деталей.

### Приёмка

Намеренно вызванная ошибка сразу даёт полную причину на экране и в журнале. Для типового сбоя не требуется повторять сценарий после дополнительной правки диагностики.

## T11. У монтажника только его замеры

### Подтверждённый дефект

Новый монтажник видит в «Мои замеры» замеры других монтажников. Сейчас клиент запрашивает все записи компании, а RLS разрешает доступ по `company_id` без ограничения по владельцу.

### Обязательная логика

- Монтажник видит, получает по realtime и может открыть **только замеры, где `measurements.user_id = auth.uid()`**.
- Менеджер видит замеры всех монтажников своей компании.
- Проёмы и фотографии наследуют те же ограничения через родительский замер.
- Ограничение реализуется не только фильтром интерфейса: обязательны серверные RLS/проверки для чтения, изменения и удаления.
- Клиентский фильтр по текущему пользователю добавить для защиты от лишних данных и корректного realtime, но не считать его заменой RLS.

### Приёмка

Два монтажника одной компании создают по замеру. А видит только А, Б видит только Б; прямой запрос/ссылка к чужому замеру и его фото запрещены. Менеджер видит оба. Новый замер монтажника сразу появляется у менеджера.

## T12. Три статуса и строгая модель «Оригинал / Копия»

### 12.1. Статусы

Остаются только три рабочих статуса:

| ID | Название | Цвет |
|----|----------|------|
| `active` | В работе | Жёлтый |
| `done` | Готов | Зелёный |
| `archived` | Архив | Серый |

- Статус `draft` / «Черновик» полностью убрать из интерфейса и новой модели.
- Новый замер сразу получает `active`.
- После «Сохранить и выйти» замер сразу появляется у менеджера.
- Существующие записи `draft` при миграции переводятся в `active`.
- «Оригинал» и «Копия» — **отдельная пометка версии, а не четвёртый статус**.

### 12.2. Менеджер

- В замере `active` менеджер может нажать «Завершить замер» → `done`.
- Из `done` может отправить в `archived`.
- Из `archived` может «Вернуть в работу» → `active`.
- Черновика и возврата через прежнюю цепочку `archived → done` больше нет.

### 12.3. Монтажник

- Поля и проёмы нельзя изменять, пока монтажник не нажал **«Доработать замер»**.
- Кнопка находится в области статуса; свободного выбора статуса у монтажника нет.
- При доработке редактируемый замер получает `active`, если у него был другой статус.
- Дальнейшие изменения происходят по правилам оригинала/копии ниже.

### 12.4. Оригинал

- Первый созданный замер всегда получает пометку **«Оригинал»**.
- Исходный оригинал навсегда сохраняется нетронутым при редактировании или удалении его содержимого.
- Удалить оригинал нельзя; можно только отправить его в архив.
- В оригинал можно **добавить новый проём**: он при этом остаётся оригиналом.
- Из оригинала нельзя удалить проём и нельзя изменить уже сохранённые данные/проём непосредственно в оригинале.

### 12.5. Копия

- При первой попытке изменить сохранённые данные/проём оригинала или удалить проём из оригинала создаётся связанная **«Копия»**.
- Оригинал остаётся без изменений; изменяется только копия.
- Копию можно редактировать многократно; повторные правки используют существующую копию, а не создают цепочку новых копий.
- Копия получает `active` при начале доработки.
- Связь копии с оригиналом и пометки «Оригинал»/«Копия» видны в приложении, списках менеджера и PDF.

### 12.6. Серверная неприкосновенность

- Правила оригинала/копии, владельца и допустимых переходов проверяются в БД/RLS/RPC, а не только скрытием кнопок.
- Операция «создать копию и применить первую правку» выполняется атомарно, чтобы не было потери или частичного изменения.
- Прямой вызов API не должен позволить удалить оригинал, удалить его проём или изменить исходные поля.
- Все существующие замеры при миграции становятся оригиналами.

## T13. Экраны монтажника: клавиатура и компактный мастер

### 13.1. Клавиатура

Исправить регистрацию и данные объекта, включая многострочные «Заметки»:

- Открытая экранная клавиатура не перекрывает активное поле.
- Контейнер прокручивается/поднимается при фокусе и по мере ввода.
- Активный курсор и вводимый текст остаются видимыми; над клавиатурой должно помещаться ещё примерно 2–3 строки текста.
- Проверить пароль при регистрации и заметки на реальном телефоне, не только web.

### 13.2. Шаг 1 «Этаж»

- Убрать вариант «3 этаж».
- Оставить четыре варианта: «Подвал», «1 этаж», «2 этаж», «Свой вариант».
- Расположить их компактно в один или два ряда.
- «Свой вариант» по-прежнему позволяет ввести другое значение.
- Этаж проёма остаётся необязательным; этап можно пропустить.

### 13.3. Шаг 2 «Помещение»

- Показывать варианты по **3 в ряд**.
- Сделать список компактным и ближе к верху экрана, без растягивания на длинный столбец.
- По возможности весь выбор помещается на одном экране телефона; читаемость и нажатие не должны пострадать.

### 13.4. Фото

Шаг «Сделать фото» заказчик принял без замечаний; внешний вид и поведение не переделывать.

### 13.5. Объединение размеров

Прежние шаги 4, 5 и 6 объединить в один экран:

- Три поля одно под другим: «Высота проёма», «Ширина проёма», «Толщина проёма».
- Эти названия остаются такими же крупными и жирными, как сейчас заголовки отдельных шагов.
- Убрать пояснения под названиями («Замерьте…» и т. п.).
- Убрать placeholder «Например, 2100» и аналогичные подсказки внутри полей.
- Единица «мм», числовой ввод и текущие пределы сохраняются.
- При выходе за пределы поле получает красную рамку и рядом отображается понятная подсказка.
- При подтверждении значений вне пределов появляется дополнительное окно **«Вы уверены?»** с подтверждением и отменой. Только после подтверждения такие значения принимаются.

## T14. Панель менеджера

### Навигация и инвайты

- В нижней навигации менеджера убрать «Мои замеры».
- «Новый замер» можно расположить в середине нижней навигации.
- Панель/кнопку «Сгенерировать код» убрать из основного окна и перенести в «Настройки».
- Содержимое и остальная логика «Настроек» обсуждаются отдельно; сейчас их не расширять самостоятельно.

### Фильтр по монтажникам

- Нажатие на монтажника подсвечивает его зелёным.
- Ниже показываются только замеры выбранного монтажника.
- Нажатие «Все» сбрасывает фильтр: показываются все замеры компании, а карточка монтажника больше не подсвечена.
- Фильтр по монтажнику работает вместе с существующими фильтрами статусов и поиском.
- Сохранить подтверждённое realtime-появление нового монтажника и новых замеров.

### Статусы

- В работе — жёлтый, Готов — зелёный, Архив — серый во всех списках, карточках и деталях.
- Переходы — по T12; прежнюю модель с черновиком не сохранять.
