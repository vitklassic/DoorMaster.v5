# ТЗ-T1. Убрать debug-переопределение роли менеджера

**Исполнитель:** Кодер (Kimi Code) · **Оценка:** 0.5 ч · **Приоритет:** P0
**Контекст:** аудит C1 (`Docs/tech/ARCHITECTURE.md` §5), стандарт ТС п.6.

## Цель
Все пользователи сейчас принудительно получают роль `manager` (`FORCE_MANAGER_ROLE = true`), поэтому монтажник попадает на панель менеджера, а вкладка «Новый замер» ведёт себя неправильно. Нужно использовать реальную роль из `profiles`.

## Детали реализации
Файл: `lib/auth/AuthContext.tsx`.

1. Удалить константу `FORCE_MANAGER_ROLE` и функцию `withDebugRole`.
2. Во всех местах, где результат оборачивался в `withDebugRole(...)` (подписка `onAuthStateChange`, `getCurrentUser().then(...)`, `signIn`, `completePasswordReset`), использовать значение как есть.
3. Логика реальной роли уже работает: `authApi.withRole` читает `role` из `profiles`, вкладки гардируются в `app/(tabs)/_layout.tsx`, `ManagerDashboard` проверяет роль сам.

## Критерии приёмки
- Новый пользователь без инвайта (создает свою компанию, роль `manager` — см. `handle_new_user`) видит панель менеджера; `initialRouteName` = manager.
- Пользователь, зарегистрированный по инвайт-коду (роль `installer`), видит вкладки «Новый замер» и «Мои замеры», вкладки «Панель» у него нет.
- Монтажник по прямой ссылке на `/manager` получает экран «Доступ запрещен» (уже реализовано в `ManagerDashboard`).
- `npm run typecheck` — без ошибок.
- Никаких упоминаний `FORCE_MANAGER_ROLE` / `withDebugRole` в коде (проверить поиском).
