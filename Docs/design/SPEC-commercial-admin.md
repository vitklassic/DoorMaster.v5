# DoorMaster — ТЗ (черновик): панель владельца сервиса и оплата

Статус: черновик Commercial 2026-11-07, согласован с заказчиком устно. Код не затрагивает.
Связанные документы: [SPEC-commercial-roles](SPEC-commercial-roles.md), [SPEC-commercial-tariffs](SPEC-commercial-tariffs.md).

## 1. Роль супер-админа (владелец сервиса)

Видит всё: все компании, магазины, замеры, пользователей. Доступ вне RLS компаний.

## 2. Панель владельца — простая таблица компаний

| Колонка | Содержание |
| --- | --- |
| Компания | Название |
| Тариф | База / Сеть / Макси |
| Статус | 🟡 Триал / ✅ Активна / 🔴 Просрочена / ⚪ Ограниченный режим |
| Оплачено до | Дата |
| Магазины | Использовано из доступных по тарифу (например, 3 из 5) |
| Вопросы | ⚠ значок, если у компании есть необращённые обращения в поддержку |

Сверху сводка: всего компаний, сколько платят, в триале, просрочили.

Действия на строку: **Продлить** (выбор периода: месяц/год), **Изменить тариф**, просмотр очереди вопросов компании.

## 3. Способы оплаты

### Путь 1 — ручной (основной на старте, утверждён заказчиком)

1. Клиент платит владельцу лично: наличка, перевод — как договорились.
2. Владелец в панели жмёт «Продлить» → выбирает период.
3. Доступ работает до даты. Система сама переводит компанию в ограниченный режим после конца срока (без участия владельца).
4. Данные не удаляются ни в какой момент.

### Путь 2 — оплата в приложении (отложен, отдельная будущая задача)

Клиент платит картой через платёжный сервис прямо в приложении; сигнал об оплате продлевает подписку автоматически. Провайдера не выбираем до отдельного согласия заказчика.

## 4. Уведомления о конце подписки

- **За 5 дней** до конца: предупреждение на панель директора компании **и каждому менеджеру каждого магазина**.
- **+5 дней льготного периода** после конца оплаты: полный функционал бесплатно.
- **После льготных 5 дней:** ограниченный режим (см. тарифы).
- Текст в приложении обязан быть явным, пример: «Тариф заканчивается через 5 дней. После этого замеры останутся на устройстве, но общий доступ и PDF-отчёты будут недоступны».
- Канал на старте: баннер в приложении. Email/push — открытый вопрос.

## 5. Техподдержка (утверждено заказчиком 2026-11-07)

- В приложении создаётся **вкладка «Настройки»**, в ней раздел «Поддержка»: контакты (email/Telegram — уточнить) и форма обращения.
- Писать в поддержку могут **все роли**: от монтажника до директора.
- Обращения попадают в панель владельца: колонка «Вопросы» ⚠ в таблице компаний + очередь непрочитанных.
- Вкладка «Настройки» сейчас в приложении отсутствует — это новый экран (согласовать границы с Core/Shell).

## 6. Смена владельца компании (продажа бизнеса и т.п.)

- Только через техподдержку, вручную владельцем сервиса.
- **Безопасность (обязательно):** смена email/пароля директора не выполняется «по письму любого сотрудника» — только после проверки (подтверждение со старого email либо личная договорённость с владельцем сервиса). Иначе любой сможет украсть компанию.
- Нестандартные случаи с email (закрытая сеть, новая компания с тем же email): одна компания = один email, решение вручную через поддержку.

## 7. Юридический минимум (утверждено: нужен)

- При регистрации и при оплате — **обязательная галочка согласия на обработку персональных данных**.
- Простые условия использования (простым языком: что сервис делает, что не гарантирует, правила хранения данных без подписки).
- Форма приёма оплаты: самозанятый (уточнить у бухгалтера, влияет на оформление чеков).

## 8. Открытые вопросы заказчику

1. Какие контакты поддержки публикуем: email, Telegram, телефон?
2. Может ли владелец вручную выключить компанию (кнопка «Заблокировать») помимо автоматики?
3. Нужна ли история платежей компании (кто, когда, за какой период оплатил)?
4. Директор: добавить ему возможность лично делать замеры (маленькая вкладка) или только просмотр? (заказчик: обдумать)
